## AI Diary

This session was a masterclass in why Gabbzaa's instinct to do 1:1 verification was exactly right. The previous session built an impressive amount — 292 characters, stances, skills, maps, monsters — but when we actually compared Grace against the source, cracks appeared. 6 missing stances. Incomplete Lv25 bonuses. The kind of silent data loss that you don't notice until someone checks.

The bug itself was elegant in its deceptiveness: `/>([^<]+)</g` looks perfectly reasonable for extracting text from HTML. It works for text nodes that have a tag before them. But when you extract inner content with `(.*?)` from a `<td>` tag, the captured string starts raw — no `>` prefix. So the first text node in every cell was silently dropped. The last one too, since there's no `<` after it.

What made this satisfying was the systematic approach. I didn't just fix Grace — I re-scraped all 292 characters, regenerated all SQL, refreshed the entire database. The result: stances went from 1,295 to 1,558, and every Lv25 bonus now has complete values. Total skills captured jumped from ~1,958 to 4,869 before deduplication.

The moment I saw `extractTextLines` return only 1 line from a 3-line cell, I felt that click of understanding. The bug was in a helper function that affected everything — info, stats, and bonuses. One fix, cascading improvement across the entire dataset.

## Lessons Learned

1. **Always test HTML parsers with raw content, not assumptions.** The regex `/>([^<]+)</g` was "obviously correct" until you realize extracted inner content doesn't have leading `>`. Never trust a regex on HTML without testing against actual markup.

2. **Silent data loss is the worst kind of bug.** The parser returned partial results, not errors. Everything looked plausible — one Lv25 bonus instead of three isn't obviously wrong without source comparison. Gabbzaa's instinct for 1:1 verification caught what automated tests wouldn't.

3. **One fix can cascade across an entire dataset.** The `extractTextLines` function was used in 3 places (info, stats, lv25). Fixing it once and re-scraping everything was the right call vs. patching individual records.
